How to use: Screen-share localhost:3000/class-materials (Overview tab) while you talk. Speak in cohort themes only — never individual scores or emails. Fits inside Block A2 of the Monday Kickoff run-of-show.

Setup before you speak

  • Survey dashboard open: Overview tab visible to students
  • Chat ready for reactions (optional: “Which number surprised you?”)
  • Remember: scales are 1–5 self-ratings, not grades

6:02 A2 · Survey themes · 3–5 min

1 · Frame it (30 sec)

Say
Before class you took a short baseline — confidence, skill, and knowledge across coding, terminal, Git, Docker, debugging, reading code, and AI tools, plus whether you’ve built an app. That’s not a test. It tells me where to spend clinic time and how fast to move in Phase 1.

2 · Normalize the baseline (45 sec)

Say
Looking at 58 responses, the cohort average is about 1.9 out of 5 across confidence, skill, and knowledge. That means most of us are beginners — and that’s exactly who this course is built for. Phase 1 starts with foundations on purpose. If you’ve already shipped apps, early weeks may feel like review — stay for the structure and the AI path, or move fast through labs you know. If you’re newer, you’re in the right room.
Do
Point to the four stats at the top of the dashboard: 58 · 1.9 · 2.0 · 1.9
Watch for
Anyone looking embarrassed — reinforce “low starting number = correct starting line”

3 · Five numbers out loud (90 sec)

Say
Five numbers from your survey — I’ll say the finding, then what it means for how we teach:
Finding Number Line you say next
Not confident writing code at all 50% We assume zero. That is fine.
Not confident debugging 57% Debugging is a skill we practice every lab — with AI as a partner, not a black box.
Never built an application 67% Your first real app is a course outcome, not homework fluff.
No Docker experience / beginner 64% Containers come with the project — not as isolated theory.
No Git knowledge yet 50% Version control starts with tiny commits once the editor is working.

Survey talking points · continued

Foothold, support, close

4 · Name the foothold (45 sec)

Say
You’re not starting from nothing. Terminal skill averages 2.3 — the strongest traditional skill. AI confidence and prompt/review skill both sit around 2.2. So here’s the plan: we lean on prompting and reviewing AI output first, then we backfill reading code, Git, and Docker so you can trust what the tools produce. That’s agentic coding in one sentence — guide the agent, read the diff, fix what’s wrong.

Relative strengths

  • Terminal / CLI — 2.3
  • AI tool confidence — 2.2
  • Prompt + review skill — 2.2
  • Learning new tools — 2.0

Close early

  • Docker — 1.4
  • Debugging confidence — 1.6
  • Writing code — 1.7
  • Git — 1.7

5 · Tie to their goals (30 sec)

Say
In the open responses you asked for the same things: learn AI for coding and agentic workflows; build basic coding and real applications; apply skills to jobs, automation, and IT; and use AI for troubleshooting and secure apps. The curriculum is aimed at those goals — tonight we start with the editor and the terminal so you have a place to work.

6 · Bridge to the rest of Block A (15 sec)

Say
So: low baseline is expected, AI is our on-ramp, and the first app is coming. Next I’ll show how the course works and where everything lives in D2L — then we install VS Code together.
Do not: Screen-share the raw spreadsheet with emails · Call out individuals · Compare students to each other · Treat 1.9 as a verdict — treat it as the map for Phase 1.

Optional · if you have 2 extra minutes

  • Switch dashboard to By question → click Debug confidence or Docker so the bar chart sells the story visually
  • Switch to Built an app? — 67% / 24% / 9% is a clean visual for project-based learning
  • Chat poll: “Which of the five numbers felt most true for you?” (emoji reactions)

Support groups (for you — don’t list names)

  • Code/debug at 1–2: foundational labs + guided debugging in Wednesday clinic
  • Docker or Git at 1: short intro before project milestones
  • No app yet (67%): one end-to-end project path through Phase 1–2
  • ~9% shipped before: peer helpers / stretch pace — not the default speed
Close on momentum: Students already want agentic workflows and real applications. The baseline is low on traditional engineering tools — that is the curriculum, not a judgment on the cohort.
