Optional Stretch Demo

Cursor · Countdown + venv + pip

Use after core labs, or as a 10–15 min preview. Say clearly: full venv labs land later (Module 03).

Why block — say before typing

Why a venv?

System Python is shared — global installs let Project A break Project B. A venv is a private toolbox for this project.

Why requirements.txt + pip?

requirements.txt = shopping list. pip install -r … installs into this venv so any machine can rebuild it.

Why Cursor here?

Same folder/terminal habits as VS Code. Tonight: folder → venv → install → run. AI help comes later.

Demo project — build live

1. Folder (prefer WSL Ubuntu on Windows)
mkdir -p ~/countdown-demo && cd ~/countdown-demo
requirements.txt
colorama==0.4.6
countdown.py
import time
from colorama import Fore, Style, init
init(autoreset=True)

def countdown(seconds: int) -> None:
    print(Fore.CYAN + f"Countdown from {seconds}...")
    for i in range(seconds, 0, -1):
        print(Fore.YELLOW + str(i)); time.sleep(1)
    print(Fore.GREEN + "Go!")

if __name__ == "__main__":
    countdown(5)
2–4. Create venv · install · run
python3 -m venv .venv
source .venv/bin/activate          # prompt shows (.venv)
pip install -r requirements.txt
python countdown.py                # 5…4…3…2…1… Go!
colorama is not built into Python. Without venv + pip, import colorama fails — that’s the “why.”
5. Optional 60-second proof
deactivate && python countdown.py   # often ImportError
source .venv/bin/activate && python countdown.py   # works
Same file. Different environment. That’s why we care about venv before real apps.
