# Contributing

## PR checklist

Before you open the pull request, check your *Files changed* tab shows exactly one file:

- [ ] `students/<your-github-username>.md` — filename matches your GitHub username
- [ ] Branch is named `add-<your-github-username>`
- [ ] All four card fields are filled in
- [ ] No edits to `_example.md`, the README, or anyone else's card

## Reviewing a classmate's PR

Leave at least one comment. Good review comments are **specific** and **kind**:

- Point at a line: "Your favorite command is `cd -` — same, nobody taught me that for years."
- Catch a real problem: "Your filename says `students/tim.md` but your GitHub username is `tim-c` — the filename should match."
- A plain "LGTM" with nothing else doesn't count for the lab.

You're practicing the muscle of reading someone else's diff and saying something useful about it. That's most of what code review is.
