Module 05 — Continue.dev on the Shared vLLM Endpoint

🎯 What you'll be able to do after this module
  • Verify that the college's shared vLLM inference endpoint is reachable from your dev environment using a curl status check
  • Query the endpoint's /v1/models route with the shared API key and identify the exact model ids it serves
  • Send chat completions to Llama 3.3 70B over the OpenAI-compatible API and explain why Llama 3.1 8B is reserved for autocomplete
  • Configure Continue.dev in VS Code via ~/.continue/config.yaml with role-separated models pointing at the shared endpoint
  • Chat about your FastAPI repo using the @file, @codebase, @diff, and @terminal context providers
  • Use tab autocomplete to write a working route, reading every ghost-text suggestion before accepting it
  • Edit highlighted code with Ctrl+I inline edits, accepting, rejecting, or partially accepting each proposed diff
  • Use agent mode to make approval-gated, multi-file changes and ship a feature through a GitHub pull request

Lessons and objectives

#LessonLearning objective
00Prerequisites CheckConfirm the deliverables from Modules 00-04 (Git, Docker Compose, the FastAPI repo, and the GitHub remote) still work and that the Continue.dev extension is installed in VS Code.
01The Inference EndpointDescribe the college's shared vLLM server — its 2x RTX A6000 hardware, the two Llama models, and their roles — and confirm the endpoint answers with an HTTP status code using curl.
02Connect to the EndpointQuery the endpoint's /v1/models route with the shared API key via curl and confirm the exact Llama model ids appear in the OpenAI-style JSON response.
03Explore the ModelsSend real chat completions to the 70B model through the OpenAI-compatible /v1/chat/completions route, use a system prompt to steer its style, and explain why the 8B model is reserved for autocomplete.
04Install + Configure Continue.devInstall Continue.dev in VS Code and write ~/.continue/config.yaml so the 70B serves chat, edit, and apply while the 8B serves autocomplete, then verify with a first chat and a ghost-text completion.
05ChatUse the @file, @codebase, @diff, and @terminal context providers to bring real repository context into Continue chat and get grounded answers about your FastAPI code.
06AutocompleteWrite a working PUT /items/{item_id} route using tab autocomplete, reading each ghost-text suggestion before accepting with Tab, refining by typing, or dismissing with Esc.
07Inline EditUse Ctrl+I inline edits to rename a function, add validation, extract a helper, and draft a test, reviewing every proposed diff before accepting, rejecting, or partially accepting it.
08Agent ModeUse Continue's agent mode to make approval-gated, multi-file changes on a feature branch, reviewing each tool call and rejecting steps that are wrong or destructive.
09Final CheckpointBuild a case-insensitive GET /items/search route with the Continue.dev + college vLLM stack, verify it with curl and Swagger UI, and ship it through a GitHub pull request.

Each lesson is one learning object with a paired lab. Work in order — completing a lab unlocks the next lesson. The module ends with a Check on Learning quiz and a hands-on final checkpoint.
