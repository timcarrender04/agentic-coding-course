Before you type

  • VS Code connected to the same Linux as Docker (bottom-left: WSL: Ubuntu or SSH: …). The whale sidebar must not say Failed to connect.
  • You can run Docker without sudo (docker run hello-world already worked).
  • Three-person teams. Name a leader. Everyone clones and runs Compose on their own machine — no watching-only.
  • Suggested split: (1) Docker — compose, logs, sidebar · (2) Research — docs/Hub + RESEARCH.txt · (3) Validate — curl, browser, compose exec psql.
  • Grok or another LLM outside the IDE is allowed. Still cite a real doc/Hub URL in RESEARCH.txt.

Free port 8080, then bring it up

docker ps
docker ps -aq | xargs -r docker rm -f

# wrong: python3 app.py    /    uvicorn app:app ...
# right:
docker compose up -d --build
docker compose ps

Open docker-compose.yml and Dockerfile. Two services: web builds this folder and serves the form + API on 8080; db is official postgres:16. app.py is copied into the web image. It is not a host command.

Prove both containers

Browser: http://localhost:8080 — add a name + email. The table should show the row.

curl -s http://localhost:8080 | grep -i signup
curl -s -X POST http://localhost:8080/api/signups \
  -H "Content-Type: application/json" \
  -d '{"name":"Ada","email":"ada@example.com"}'
docker compose exec db psql -U roster -d roster -c "SELECT name, email FROM signups;"
docker compose logs web --tail=20

Whale sidebar should show web and db running.

What “done” looks like

  • docker compose ps shows web Up and db healthy (or Up).
  • GET/POST /api/signups hit the web container, not a local Python process.
  • From web, Postgres hostname is the service name db (not localhost).
  • Named volume pgdata keeps rows after docker compose down then up (down -v wipes data).
  • You did not run python/uvicorn on the host.
  • Three names on the team; each person has compose ps green.
